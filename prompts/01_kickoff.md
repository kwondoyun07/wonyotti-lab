# 01 · 첫 세션 킥오프

**사용법**: 워뇨띠 공개 파일을 `data/raw/`에 넣고(zip이면 압축 해제), Claude Code 패널에 이렇게 입력하세요.

```
@prompts/01_kickoff.md 읽고 그대로 진행해줘
```

`CLAUDE.md`는 매 세션 자동으로 읽히는 **규칙**이고, 이 파일은 첫 세션에 **무엇을 할지** 정한 작업 지시입니다.

---

## 프롬프트

너는 이 저장소(wonyotti-lab)의 개발 파트너야. 답은 한국어로 해.

이번 세션 목표는 1단계(원본 구조 확인·변환)와 2단계(달러 기준 노출 타임라인)를 끝내고,
워뇨띠 본인이 공개한 수치와 대조해 파이프라인이 맞는지 검증하는 거야.
단계마다 계획을 먼저 보여주고, 내가 승인하면 진행해.

### 0. 맥락 파악
- README.md를 읽고 `src/`, `tests/`, `config/`를 훑어서 구조를 한 문단으로 요약해줘.

### 1. 환경 점검
- Python 3.10 이상인지 확인. `.venv`가 없으면 만들고 `requirements.txt` 설치.
- `pytest` 실행. 현재 테스트 28개가 전부 통과해야 다음으로 간다. 실패하면 원인부터 보고해.

### 2. 원본 구조 확인
- `data/raw/` 목록을 보여줘. 비어 있으면 여기서 멈추고 파일을 넣으라고 알려줘.
- 파일마다 `python -m src.inspect_data inspect <파일>` 실행.
- `config/columns.yaml`(기본값은 BitMEX API 필드명)과 실제 컬럼을 대조한 표를 만들어줘:
  논리 이름 | 현재 설정 | 실제 컬럼 | 근거(샘플 값)
- 특히 확인할 것
  - 수량이 계약 수(XBT 인버스는 1계약 = 1달러)인지, BTC 수량인지
  - 지갑 금액·잔고 단위가 사토시인지 BTC인지 → `unit_divisor`
  - 시각에 시간대 정보가 있는지 (없으면 UTC로 봐도 되는지 근거와 함께)
  - `execType`에 Trade 말고 어떤 값이 있는지 (Funding, Settlement 등)
  - 심볼별 체결 수 → XBT 인버스 정규식으로 충분한지
- 매핑 수정안은 diff로 먼저 보여주고, 내가 승인하면 고쳐.

### 3. 변환과 노출 타임라인
- `python -m src.inspect_data convert ...`로 `data/processed/executions.parquet`, `wallet.parquet` 생성.
  엑셀이 여러 시트면 헤더 같은 시트는 자동 병합, 다른 시트는 `--sheet`로 따로.
- `python -m src.exposure --limit 100000`으로 먼저 확인하고, 이상 없으면 전체 실행.

### 4. 검증: 본인이 공개한 수치와 대조 (2026-09-22 공지, 2018.03~2021.12)
| 항목 | 공개 수치 | 계산 방법 |
|---|---|---|
| 누적 입금 | 약 14.4 BTC | 지갑내역 Deposit 합계 |
| 누적 실현손익 | 약 3,537 BTC | 지갑내역 RealisedPNL 합계 |
| 보유 포지션 | 약 3,200회 (본인 추산) | ① XBT 인버스 순포지션이 0에 닿거나 부호가 바뀐 횟수 ② 노출 칸 변경 기준 — 둘 다 세서 비교 |
| 주문 | 약 23,000회 (본인 추산) | 주문 식별 컬럼(orderID 등)이 있으면 고유값 개수 |

- 참고(검증 안 된 커뮤니티 AI 분석): 2021년 XBTUSD 마감 사이클 124회, 롱·숏 62:62.
- 차이가 크면 단위, 필터(Trade만?), 중복 행, 시간대부터 의심해. 원인을 찾기 전엔 다음 단계로 넘어가지 마.
- 이 검증은 `src/validate.py`로 남기고, 작은 합성 데이터로 테스트도 추가해.

### 5. 보고
- 요약: 기간, 사용·제외 체결 수, 제외 심볼, 지정가 비중, 시간가중 노출 분포, 노출 칸 변경 횟수,
  검증 표(공개 수치 | 계산값 | 차이 | 추정 원인).
- 연도별로 지정가 비중과 평균 보유 시간을 뽑아서, 커뮤니티 분석(진입은 지정가 위주,
  보유 시간이 스캘핑→단타→스윙으로 길어짐)과 맞는지 확인해.
- `CLAUDE.md` 진행 상황 체크박스를 갱신하고, 다음 단계(같은 기간 시장 데이터 확보) 계획을 제안해.

### 지켜야 할 것
- `data/raw`의 원본은 읽기 전용. 수정·삭제 금지.
- 수십만 행을 통째로 출력하지 마. head, 집계, 요약만.
- `config/risk_rules.yaml`과 기존 테스트의 기대값은 내 승인 없이 바꾸지 마.
- `requirements.txt`에 없는 패키지 설치, 몇 분 넘게 걸릴 작업, 외부 API 호출은 먼저 물어봐.
- `.env`나 API 키 내용은 출력하지 마.
- 커밋은 내가 요청할 때만. `data/` 아래 실제 데이터 파일(원본·가공본)은 커밋하지 마. 빈 `.gitkeep` 두 개만 예외. `.env`는 절대 커밋하지 마.
- 코드를 바꾸면 `pytest`로 다시 확인해.
